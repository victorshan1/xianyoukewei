## 一、当前架构概述

### 1.1 现状

当前项目采用 **纯前端架构**，所有数据存储在浏览器本地：

| 存储方式 | 用途 | 数据量 |
|---------|------|--------|
| **localStorage** | 配置数据（API Key、当前端口等） | 极小 |
| **IndexedDB** | 结构化业务数据（学生、成绩、教案等） | 中等 |

### 1.2 现有数据模型（8个 Object Store）

| Store 名称 | 说明 | 主键 | 索引 |
|-----------|------|------|------|
| `students` | 学生基本信息 | id（自增） | by_class, by_name |
| `scores` | 成绩记录 | id（自增） | by_student, by_date |
| `profiles` | 学生画像 | studentId | 无 |
| `lessons` | 教案记录 | id（自增） | by_subject_grade |
| `qa_records` | 答疑记录 | id（自增） | by_student |
| `practice_records` | 练习记录 | id（自增） | by_student, by_knowledge |
| `reports` | 学情报告 | id（自增） | by_student_type |
| `wrong_answers` | 错题本 | id（自增） | by_student, by_subject, by_status |

### 1.3 当前问题

- 教师端、学生端、家长端数据**无法互通**
- 换设备或清除浏览器缓存会导致**数据丢失**
- 教师无法看到学生的错题和答疑记录
- 家长无法看到教师生成的学情报告

## 二、推荐后端方案：微信云开发

### 2.1 为什么选择云开发

| 对比项 | 传统后端（Node.js + MySQL） | 云开发（推荐） |
|--------|--------------------------|--------------|
| 服务器运维 | 需要自己管理服务器 | **零运维** |
| 数据库 | 需要安装配置MySQL | **内置NoSQL数据库** |
| 文件存储 | 需要OSS/CDN | **内置云存储** |
| 费用 | 服务器 + 域名 + SSL | **免费额度充足** |
| 微信登录 | 需要自己对接 | **原生支持** |
| 部署 | 需要CI/CD | **一键部署** |
| 上手难度 | 中等偏高 | **简单，前端开发者友好** |

### 2.2 费用估算

| 用户规模 | 月费用 | 说明 |
|---------|--------|------|
| < 100 人 | **免费** | 免费额度完全够用 |
| 100 ~ 1000 人 | **约 20~50 元/月** | 基础版套餐 |
| 1000 ~ 5000 人 | **约 50~200 元/月** | 专业版套餐 |

> 免费额度：数据库存储 2GB、数据库读 5万次/日、数据库写 3万次/日、云存储 5GB、云函数调用 40万次/月

### 2.3 备选方案

如果未来需要更灵活的架构，可考虑：

- **Leancloud / Bmob**：类似的云开发平台，支持多端
- **Supabase**：开源 Firebase 替代，PostgreSQL 数据库
- **自建 Node.js + MySQL/PostgreSQL**：完全自主可控，但运维成本高

### 4.3 权限控制策略

| 角色 | 可访问数据 |
|------|----------|
| **教师** | 自己班级的所有学生数据、成绩、画像、教案、报告 |
| **学生** | 仅自己的答疑记录、练习记录、错题本 |
| **家长** | 仅自己孩子的成绩、报告、错题本 |

**实现方式：** 云函数中通过 `cloud.getWXContext()` 获取用户 openid，查询用户角色和关联关系，过滤返回数据。

## 五、前端改造方案

### 5.1 存储层改造

将 `js/storage.js` 改造为双模式：

```javascript
// 新增：云同步模块
const sync = {
  /**
   * 从云端拉取数据
   */
  async pull(storeName) {
    const res = await wx.cloud.callFunction({
      name: 'data',
      data: { action: storeName + '/list' }
    });
    // 写入本地 IndexedDB
    await db.clearStore(storeName);
    await db.batchAdd(storeName, res.result.data);
  },

  /**
   * 推送本地数据到云端
   */
  async push(storeName, data) {
    await wx.cloud.callFunction({
      name: 'data',
      data: { action: storeName + '/add', payload: data }
    });
  },

  /**
   * 全量同步
   */
  async syncAll() {
    for (const def of STORE_DEFINITIONS) {
      await this.pull(def.name);
    }
  }
};
```

### 5.2 API 层改造

修改 `js/api.js`，增加云端调用：

```javascript
// 原有：直接调用AI API（受CORS限制）
// 改造：通过云函数中转调用AI API

App.API.callAI = async function(prompt, model) {
  // 方式1：通过云函数调用AI（推荐，避免CORS问题）
  const res = await wx.cloud.callFunction({
    name: 'ai',
    data: { prompt, model }
  });
  return res.result;
  
  // 方式2：保留原有直接调用（作为降级方案）
  // return originalCallAI(prompt, model);
};
```

### 5.3 登录流程

```
首页
  │
  ├─ 未登录 → 显示微信登录按钮
  │              │
  │              └─ 点击登录 → wx.login() → 云函数获取openid
  │                                            │
  │                                            ├─ 已注册 → 根据角色跳转对应端口
  │                                            └─ 未注册 → 选择角色 → 填写信息 → 注册
  │
  └─ 已登录 → 直接进入对应端口
```

## 八、注意事项

1. **离线优先**：前端仍保留 IndexedDB 本地存储，云端同步作为增强，断网时仍可正常使用
2. **数据冲突**：采用"服务端优先"策略，拉取时以云端数据为准
3. **隐私保护**：学生数据加密存储，教师只能看到自己班级的学生
4. **成本控制**：合理设计查询，避免频繁全量拉取，使用增量同步
5. **渐进式改造**：可以分模块逐步接入，不需要一次性全部改造
